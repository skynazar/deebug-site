Security research & smart contract auditing.

Independent security research focused on the parts of crypto infrastructure that scanners can't reach: exchange internals and on-chain accounting.

Background is building this software rather than only breaking it — matching engines, order management, settlement and custody integration, token issuance and vesting contracts. That's the lens: most high-severity bugs in this domain aren't memory safety or injection, they're broken invariants in code that looks perfectly reasonable.

Focus

  • matching engineOrder lifecycle, balance locking, partial-fill accountingRefund asymmetry, placement races, fee rounding, cancel-replace idempotency
  • settlementDeposit, withdrawal and reconciliation pathsFinality assumptions, reorg handling, dust accumulation, cross-system seams
  • contractsVesting, allocation and token sale logicCliff boundaries, linear release rounding, revocation, claim reentrancy
  • defiShare accounting and value conservationInflation attacks, rounding direction, oracle assumptions, invariant fuzzing

Method

Read the docs, write down every guarantee the protocol claims, turn each into an executable invariant, then let a fuzzer try to break it. A failing invariant is evidence. Everything else is a hypothesis until it's reproduced.
